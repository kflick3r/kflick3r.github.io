This week I moved StudySync from the planning stage into development. Based on feedback on my project proposal, I decided to keep the initial technical stack simple and build the MVP using Python and Streamlit. Since I had never used Streamlit before, a large part of this week's work involved learning how Streamlit applications are structured while building the first functional version of the StudySync interface.


<!--more-->

# What I Worked On

Before coding, I refined the MVP and created a low-fidelity wireframe for the application's main screens. The current MVP focuses specifically on Natural Language Processing (NLP) course material. A student will provide their notes once and then choose between four study tools: a Review Guide, Flashcards, Multiple Choice questions, or Short Response practice.

[View the full StudySync MVP](https://github.com/kflick3r/StudySync/blob/main/docs/MVP.md)

Before beginning the Streamlit implementation, I mapped out the main StudySync workflow and the interactions I wanted to support. The goal was to keep the interface simple while allowing students to move freely between study tools without having to re-enter their course material.

The main workflow is:
**Add Notes → Study Tools → Review Guide / Flashcards / Multiple Choice / Short Response**

The wireframe also helped me think through smaller design decisions, such as preserving notes when a student chooses to edit them and providing navigation between all four study tools.

[View the full StudySync Wireframe](https://github.com/kflick3r/StudySync/blob/main/docs/wireframe.md)

I started by setting up a Python virtual environment, installing Streamlit, and creating a basic application that accepts pasted NLP course notes. I then learned how Streamlit reruns a Python script when a user interacts with the application and used Session State to preserve the student's notes while they move through the app.

From there, I converted StudySync into a multipage application. The current prototype includes pages for:
- Adding or editing course notes
- Choosing a study tool
- Review Guide
- Flashcards
- Multiple Choice
- Short Response

The four study tools are placeholders for now, but the navigation between them is functional.

I also created a reusable `components.py` file for the footer of each of the study tools. The navigation logic is shared between all four of the study pages. Instead of duplicating the same navigation code on every page, each study page can call the same function. I customized the navigation so students can switch between study tools, return to the Study Tools page, or edit their notes.

Editing notes also introduced another design consideration. Rather than immediately deleting the student's existing notes, StudySync displays a confirmation dialog and preserves the current notes in the text area for editing. Once the AI-generated portions of the application are implemented, changing the source notes will reset resources and practice progress that were generated from the previous version of those notes.

This week gave me my first experience with Streamlit and introduced several concepts I will continue using throughout the project, including widgets, Session State, multipage navigation, columns, dialogs, and reusable Python components.

# **Week 4 Progress**

This week I:

* Finalized the NLP-focused MVP and created a low-fidelity wireframe for the main StudySync workflow.
* Set up Streamlit and built the initial multipage application structure.
* Added Session State so course notes persist as users move between pages.
* Created the Study Tools page and placeholder pages for all four study modes.
* Built reusable navigation components for moving between study tools.
* Added an Edit Notes workflow that preserves existing notes and asks for confirmation before returning to edit them.


# **Next Steps**

The current milestone is a functional Streamlit application shell. The next major step will be connecting StudySync to an LLM API and using the student's saved NLP course material as context to generate the first Review Guide. This will begin the prompt and context design portion of the project.
